# AI 协作对话记录

这里记录开发 Mini Agent 时和 AI 编程工具的主要技术对话。候选人负责定范围、定设计和验收；AI 负责按这些决定实现、写测试和改文档。下面是按主题整理的核心对话，不是聊天工具的原始导出。

## 读题和范围

候选人：先读第四题。要做的是能自己调用工具的 Mini Agent，不是直接生成 TODO 报告。基础能力、四个工具、至少三个任务、Trace 和设计说明都要有。先告诉我你理解的交付范围，先不要写代码。

AI：题目要求主循环、工具注册和调用、参数解析、工具结果回到 Agent、一轮里可以连续调用多个工具、最终答案、轮数上限、失败处理。工具至少是 `read_file`、`write_file`、`search_text`、`calculator`。还要自建 workspace、至少三种任务、一份完整 Trace，以及 README、使用说明、AI 对话、`AI_USAGE.md` 和设计说明。可选项里有 Schema、权限、计划、压缩、恢复、子代理等。

候选人：范围就按基础十项先做完。多轮对话不做，一句任务结束进程就退出。语言用 Python，依赖只用标准库，测试用 pytest。Mock 和真实模型必须走同一个主循环，不能做两套 Agent。计算器不许用 `eval`。文件不许读出 workspace。没有密钥时不许编造真实模型 Trace。你把这些写成计划、设计、决定和门禁，阶段做完再写代码。

AI：按这个收口。阶段 0 只写文档。每个后面的阶段限定能改的目录，并先跑验收命令再记完成。Mock 用固定任务句式产生决定，但文件内容和合计必须来自工具返回。

## 循环和工具怎么分

候选人：设计不要写成业务脚本。循环不知道销售额怎么加，也不知道 TODO 怎么分类。模型只产出决定，工具只做一件事，记录只落盘。你按这个四层写设计，并回答题目里的结束条件、无限调用和失败处理。

AI：主循环每轮把消息交给 `decide`，有工具就执行并把结果追加回去，只有最终答案才结束。轮数默认 12。同一工具、同一参数连续失败两次就停。工具失败变成 `ok=false` 的文本，不把异常抛出循环。

候选人：同一轮如果又有工具又有最终答案，只能执行工具。结束必须是单独一轮。否则模型还没看见结果就可以宣布完成。路径沙箱和权限是两回事，后面做权限时不要混进「路径超出 workspace」。

AI：按这个改决定的处理顺序。`plan` 只是附注，不能代替工具调用。

## 实现基础循环

候选人：计划冻结了。从 workspace 生成、四个工具、Mock、主循环，到命令行，一阶段一阶段做。每阶段测试通过再继续。四句任务的原文只放一处，Mock 和实跑脚本共用。

AI：按阶段落地。`read_file`、`write_file`、`search_text`、`calculator` 进注册表。Mock 按原文关键词分类，下一步看工具结果。销售合计从读到的 CSV 拼表达式，再抄计算器的返回值。`scripts/run_tasks.py` 跑四句任务并写 Trace。

候选人：测试跑不起来。你看收集错误。

AI：`tests/test_openai_adapter.py` 里响应类的注解引用了自身，文件没有 `from __future__ import annotations`，收集阶段就是 `NameError`。补上之后再跑。

候选人：越界任务本身就应该失败一次然后停。你的检查却要求每条 Trace 都有两段工具调用，把正确行为判失败了。按任务种类分开检查。

AI：越界任务只要求一次失败的 `read_file` 和含「路径超出 workspace」的最终答案。其它任务仍检查多步工具。

候选人：没有密钥时，workspace 里上一轮写出的报告不见了，摘要还写着通过。先查是不是脚本在确认环境变量之前就重新生成了材料。

AI：是。`generate` 写在读取 `OPENAI_API_KEY` 之前，缺密钥的那次把 `todo-report.md`、`report.md`、`summary.md` 删了。把生成挪到凭证检查之后，并加一条回归测试：缺密钥时不改已有报告。

## 接上 DeepSeek

候选人：真实模型用 DeepSeek。基地址是 `https://api.deepseek.com`，不要加 `/v1`，程序只在后面接 `/chat/completions`。模型名用 `deepseek-flash`。密钥只放在我自己的环境里，不要写进仓库。真实模型的结果只记录，不要用 Mock 的固定句子判对错。

AI：适配器按这个地址发请求。超时 30 秒，网络错误和 5xx 最多再试 2 次，4xx 不重试。助手正文非空时记为 `Plan`。不从回复里拆计划修订。

候选人：四次实跑我看过了。前三个任务的数字来自工具，越界任务没有去读 workspace 外面。过程留在 `docs/traces/openai/`。

## 拓展一项一项做

候选人：基础做完了。拓展按计划来：权限、计划、失败后的计划修订、压缩、边跑边打印、文件不存在的提示、工具查找、一层子代理。一次只做一个，做完测试再提交。默认行为不能把原来四个任务改掉。`delegate` 默认关闭。`tool_search` 不能把旧工具从规格里拿掉。

AI：按这个顺序改循环和注册表。`--allow` 在执行函数之前拒绝。计划写在第一次工具调用之前。`plan_update` 只在上一轮工具失败时写入，真实适配器不填这个字段。超过 24000 字时，除最近一条工具结果外收成一行。命令行默认打印 `tool: 名称`，`--no-stream` 改回结束时再打印。线上 HTTP 仍然一次返回。

候选人：压缩和打印顺序不要靠四句短任务硬触发。短任务就应该没有压缩标记。压缩用自动测试把门槛暂时降下来看。子代理 Mock 规划不了那句自由任务，用假模型证明只有一层；真实模型我另外跑。

AI：自动测试放在临时目录，不覆盖已经留下的 Trace。`delegate` 再调用同一个 `run_agent`，子循环最多 6 轮，并且不再注册 `delegate`。

## 恢复提示把请求弄坏了

候选人：单独看恢复任务时，缺文件之后有提示，像是对的。整批用 DeepSeek 重跑时，恢复那次却停了。你看 Trace 和接口返回的错误，是不是要修。

AI：模型在同一轮里同时返回了 `read_file data/missing.txt` 和 `search_text`。旧逻辑在第一个失败结果后面立刻插入了恢复提示，第二个工具结果被挤到用户消息后面。接口要求带 `tool_calls` 的助手消息后面必须先是对应的工具消息，所以下一次请求返回 400。Mock 每次只发一个工具，单测没覆盖这种顺序。

候选人：提示还是要有，但不能插在这一轮的工具结果中间。修完用测试把「先全部工具结果，再恢复提示」钉住。我再单独重跑这一次。

AI：提示先暂存，这一轮每个工具结果都写入之后再追加。新增的测试让同一次决定里既读缺失文件又搜索，检查下一轮看见的角色顺序是助手、工具、工具、用户提示。

候选人：重跑之后，三个工具结果都在，恢复提示在它们后面，然后计算器得到 101，写入了 `summary.md`。这次可以留下。

## 一次跑完和说明

候选人：`run_tasks.py` 不要只跑原来四句。能在本地确认的拓展也放进这一次。同一句不要因为计划、恢复提示再跑第二遍。你先说明会不会覆盖我已经留下的 DeepSeek Trace。

AI：Mock 只重写 `docs/traces/mock/` 和 `docs/results/mock.md`。真实模型那条才会重写 `docs/traces/openai/`。`docs/traces/deepseek-e*` 不在这条命令的输出目录里。计划和恢复提示直接查看四个任务自己的 Trace。压缩、打印顺序、空查询和一层子代理由自动测试判定，不另存一份 Trace。

候选人：设计说明是给别人看的产品设计，重点写 Agent 本身：循环、消息、工具、失败、停止。固定任务可以提，不能写成测试说明书。写短了不行，要按代码写全。题目那七个问题单独放在最后一节，详细回答。写完你再对照代码，不要凭记忆。

AI：按 `loop.py`、注册表、Mock 和适配器重写。核对时发现 `tool_search` 的查找范围写成了「当前注册表」，代码其实是固定的五项，不包括 `delegate`。已改成和函数一致。文末第 14 节回答七个问题。

候选人：AI 对话和 `AI_USAGE.md` 也重写。不要贴原始聊天。写成我们怎么配合：我定设计，你落地；我看到问题再问你，你给出修法并改代码。
