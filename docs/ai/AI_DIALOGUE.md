# AI 协作对话记录

这里记录考试期间与 AI Coding 工具的主要对话。只记已经发生的内容。后续阶段若出现错误判断，追加在对应阶段，不回写成本来就有的结论。

## 阅读题目

候选人要求先仔细阅读第四题。AI 读了 `exam_questions/q4.md`，确认交付物是一个可自主调用工具的 Mini Agent，而不是直接写死 TODO 报告和销售合计。

题目要求：

- 工具至少有 `read_file`、`write_file`、`search_text`、`calculator`。
- Agent 主循环要根据工具结果决定下一步，并限制轮数。
- 候选人自建 workspace，至少设计 3 个不同类型的任务。
- 提交源代码、README、使用说明、测试材料、执行结果、完整 Trace、AI 对话、`AI_USAGE.md` 和设计说明。

## 先定计划再写代码

候选人要求详细的项目计划书，并且每一步做什么都要记下来，避免主线走偏、后面越写越差。

AI 先确认了两个会改变实现的选择。候选人的回答是：

- 语言：Python。
- 模型：Mock 和真实模型都要跑通并交付结果。

据此写成八个阶段：文档冻结、测试材料、工具、Mock、主循环、真实模型适配器、CLI 实跑、文档收口。计划里写明本环境当时没有模型密钥。没有密钥时不做假的真实模型 Trace。

## 执行节奏

候选人问这是不是一上来就一次性做完。AI 回答按阶段验收，不一次写完全部代码。

候选人再问「也就是不能一步一步来吗」。这说明前一条回答把节奏说拧了。实际约定是可以、并且应当一步一步来：一个阶段验收完，再进入下一个阶段。

候选人又问「就是他不停会一直做完吗」。约定收成：每做完一个阶段就停，等查看后再继续。阶段 0 只写计划书、设计说明和门禁。

## 按计划实现

后续指示是按已写好的分阶段计划完成全部待办，并且不要改计划文件本身。实现仍按阶段 0 的目录和验收来做，只是同一次会话里连续做完，没有在每个阶段停下来等待回复。

实现过程中暴露并处理了三件事：

1. OpenAI 适配器测试在收集阶段就因类型注解失败。补上 `from __future__ import annotations` 后，测试才进入真正的断言。
2. 越界任务只有一轮失败的工具调用。检查 Trace 时如果一律要求两轮工具调用，会把符合设计的停止判失败。检查改成按任务种类区分。
3. 缺少密钥时，任务脚本先清空了 workspace，Mock 已生成的报告被删掉。生成材料改到凭证检查之后，并加回归测试，然后重新执行 Mock 任务。

真实模型没有密钥。适配器只做了夹具测试，没有编造 `docs/traces/openai/`。
