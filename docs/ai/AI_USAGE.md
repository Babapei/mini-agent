# AI 使用记录

Mini Agent 由候选人和 AI 编程工具一起完成。候选人定范围、架构和验收标准，并在每阶段查看运行结果。AI 按这些决定实现代码、测试和文档。发现 AI 的输出和设计不一致时，由候选人指出，AI 给出修法并落地。

## AI 参与了哪些环节

- 阅读第四题，整理基础能力、工具、测试材料、可选项和交付物。
- 把候选人确定的阶段计划、设计说明、决定和门禁写成文档。
- 实现 workspace 生成、四个基础工具、Mock、主循环、OpenAI 兼容适配器、命令行和四句任务的实跑脚本。
- 按拓展计划逐项实现权限、计划、计划修订、上下文压缩、边跑边打印、恢复提示、`tool_search` 和一层子代理，并补上对应测试。
- 用候选人提供的 DeepSeek 配置实跑。密钥没有写入仓库。
- 在候选人指出 Trace、测试和文档问题后修改实现，并按当前代码重写设计说明。

## 哪些关键设计由候选人决定

- 先写计划和设计，再写代码。基础阶段一次只做一个阶段，验收通过再继续。
- 实现语言用 Python。运行依赖标准库，测试用 pytest。本机用 Python 3.9.6。
- 一句任务结束进程就退出。不做多轮对话。
- Mock 和真实模型共用同一个主循环、同一套工具和同一个 `Decision`。没有密钥时不编造真实模型 Trace。
- 文件工具限制在 workspace 内。计算器使用语法树，不使用 `eval`。报告中的合计必须来自计算器的返回值。
- 四句任务的原文只放在 `mini_agent/tasks.py`，Mock 和实跑脚本共用。
- DeepSeek 的基地址使用 `https://api.deepseek.com`，不追加 `/v1`。模型使用 `deepseek-flash`。真实模型的结果只记录，不按 Mock 的固定句子判对错。
- 拓展按权限、计划、计划修订、压缩、打印、恢复提示、工具查找、子代理的顺序做。`delegate` 默认关闭，只有一层。`tool_search` 不隐藏四个旧工具。
- 同一句提示词在一次跑完里只执行一次。计划和恢复提示查看这次 Trace，不为此再跑一遍。
- 设计说明写 Agent 本身。题目要求的七个问题放在文末单独回答。

## AI 出现过哪些错误判断

- 把「分阶段做」说成可以在一次无人确认的过程里连续写完。候选人要的是每阶段先看结果。
- 适配器测试文件在收集时 `NameError`。响应类的类型注解引用了自身，文件却没有 `from __future__ import annotations`，导致测试还没开始执行。
- 用「至少两段工具调用」检查全部任务。越界任务按设计只失败一次就停止，被误判为失败。
- 实跑脚本在检查 OpenAI 环境变量之前就重新生成 workspace。缺少密钥的那次运行删掉了已经写出的三份报告，摘要仍显示通过。
- 恢复提示插在同一轮的两个工具结果中间。DeepSeek 在下一步返回 400：带 `tool_calls` 的助手消息后面必须先是对应的工具消息。Mock 每次只产生一个工具调用，原有测试没有覆盖这个顺序。
- 设计说明一度按题目问题分节，后又写进大量验收脚本，再改时把 Agent 本身写短了。`tool_search` 曾被写成搜索当前注册表；代码里的查找范围是固定的五项，不包括 `delegate`。

## 候选人如何发现并修正

- 连续追问执行方式之后，把阶段 0 收成只写文档，之后每个阶段有允许修改的目录、验收命令和完成记录。
- `python3 -m pytest` 的收集错误暴露了注解问题。补上 future import 后重新运行。
- 对照越界任务的 Trace，要求检查按任务种类分开。越界只断言一次失败调用和「路径超出 workspace」。
- 看到缺密钥之后报告文件消失、摘要仍为通过，要求先查脚本顺序。生成材料移到凭证检查之后，并增加回归测试。
- DeepSeek 重跑恢复任务失败后，要求查看接口错误。确认是恢复提示的位置。改为等本轮全部工具结果写完再追加提示，并用同一次决定里的两个工具调用锁住这个顺序。候选人重新跑通这一次后才留下记录。
- 审阅设计说明时要求按代码写 Agent 的完整设计，七个问题单独放在最后。写完后对照实现复核，把 `tool_search` 的查找范围和 Mock 无法规划时的原句改成与代码一致。
