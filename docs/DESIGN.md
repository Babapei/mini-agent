# Mini Agent 设计说明

Mini Agent 是一个本地命令行程序。调用方给出一句自然语言任务和一个工作目录，程序在这个目录里反复向模型要决定、执行模型点名的工具、把工具结果交回模型，直到得到最终答案或确认无法继续，然后进程退出。

工作目录里的文件正文、搜索命中和数字计算都只来自工具的返回值。循环不打开这些文件，也不自己做加减乘除。这一次进程只处理这一句任务。进程退出之后，没有留下可以接着说的会话。

## 1. 程序对外的一次运行

入口是 `python3 -m mini_agent run "<任务>"`。

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `--workspace` | `workspace` | 工具能够访问的根目录 |
| `--llm` | `mock` | `mock` 为本机固定步骤；`openai` 为 OpenAI 兼容的 HTTP 接口 |
| `--max-steps` | `12` | 父循环最多向模型要多少次决定 |
| `--trace-dir` | `docs/traces` | 写下 `trace.md` 和 `trace.jsonl` |
| `--allow` | `read,write,compute` | 本次运行允许的权限，逗号分隔 |
| `--no-stream` | 关闭 | 结束后再把最终答案打到标准输出 |
| `--sub-agent` | 关闭 | 注册 `delegate`，允许把一句子任务交给下一层 |

下面几种情况在进入循环之前就以退出码 2 结束，不调用模型，也不改工作目录：工作目录不是已有目录；轮数小于 1；`--allow` 里出现三种权限以外的词；选择 `openai` 时缺少 `OPENAI_API_KEY`、`OPENAI_BASE_URL` 或 `OPENAI_MODEL`。

正常结束时退出码为 0。标准输出是最终答案。标准错误打印三行：`status`、`steps`、`trace`。没有 `--no-stream` 时，每个工具在真正执行之前还会立刻打印 `tool: 工具名`，最终答案在产生的那一刻打印，而不是攒到进程结束。`--no-stream` 只改变这个打印时机，不改变模型看见的消息，也不改变 Trace。

`status` 有三个值。

- `final`：某一轮的决定里没有工具调用，只有最终答案。
- `step_limit`：已经向模型要满了允许的轮数，仍没有结束。文本为「无法继续：已达到最大轮数 N。」
- `cannot_continue`：模型没有给出工具调用或最终答案；模型响应无法使用；或者同一个工具带着同一组参数连续失败了两次。文本写明停在哪一种情况。同一签名失败时，还会写上工具名、参数和最后一次错误。

未完成不会被写成已完成。三种结束都有一段给人读的文字。

## 2. 内部分成四层

四层只通过消息、决定和工具结果交接。

**循环**在 `mini_agent/agent/loop.py`。它保存消息列表，每轮调用 `decide`，按决定执行工具，把结果追加回去，并掌握轮数、连续失败、计划何时落盘、恢复提示插在哪里、上下文何时压缩。它不知道 CSV 如何求和，也不知道 TODO 如何分类。

**模型**在 `mini_agent/llm/`。两边后端的方法签名相同：`decide(messages, tools) -> Decision`。Mock 在进程内返回决定。OpenAI 兼容适配器把同一份消息发到 HTTP。循环不分支去关心决定从哪来。

**工具**在 `mini_agent/tools/`。注册表按名称找到一项，先查权限和参数，再调用函数。函数返回一段文本，或通过失败结果返回一段错误。工具不选择下一次该调用谁。

**记录**在 `mini_agent/trace/`。循环每发生一件已经确定的事，就让记录器写一节。记录器不把内容喂回模型，也不否决决定。

边界可以收成四句话：选择行动的是模型，接触工作目录的是工具，决定何时停止的是循环，把过程写成文件的是记录器。

## 3. 一次决定里有什么

模型每次交回一个 `Decision`。其中只有两类内容会让循环采取行动。

**工具调用** `tool_calls`。一项包含名称、参数对象、调用编号。一轮可以有多项，循环按列表顺序执行，不会并行，也不会自行重排。

**最终答案** `final_answer`。一段结束文本。循环只在这一轮的 `tool_calls` 为空时采用它。若同一次决定里两者都有，循环执行工具，丢弃这次的最终答案。任务若要结束，模型必须再单独给出一轮：没有工具，只有最终答案。这样工具结果一定先进上下文，模型才有机会根据结果结束，而不是在还没看见结果时就宣布完成。

其余字段是附注，不是行动。

| 字段 | 循环怎么用 |
| --- | --- |
| `thought` | 写入本轮 `Agent Decision`，并作为助手消息的正文 |
| `plan` | 仅当这是本次运行的第一次工具调用，且这段文字非空。写入 Trace 的 `Plan`，整次运行只写一次 |
| `plan_update` | 仅当上一轮最后一个工具失败，且这段文字非空。写入 Trace 的 `Plan Update` |
| `usage` | 真实接口带回的 token 计数。有则写入本轮决定，没有则省略 |

`plan` 和 `plan_update` 不能代替一次工具调用，也不能让循环停止。它们只是附在同一次决定上的文字。真实接口会把助手消息里的非空正文当作 `plan`，但不会从回复里拆出 `plan_update`。因此 DeepSeek 的 Trace 可以有计划，没有计划修订。Mock 会在它的固定步骤里显式带上这两段文字。

## 4. 消息列表

角色只有四种：`system`、`user`、`assistant`、`tool`。

运行开始时列表里两条消息。第一条是系统提示。命令行从 `docs/prompts/system.md` 读入；若调用方没有传入，循环使用一段更短的内置提示，要求只通过工具读写和计算，算术交给 `calculator`，路径留在工作目录内，结束时直接给出最终答案。第二条是用户的那句任务。Trace 的 `User` 节只记这句任务，不记系统提示。

此后列表只增加三类消息。

- 助手消息：这一轮的 `thought`。若有工具调用，消息上还挂着这些调用和编号。
- 工具消息：对应一次调用。字段有工具名、`tool_call_id`、`ok`、文本。文本是截断之后的结果，和 Trace 里的 `Tool Result` 相同。
- 一条用户消息形式的恢复提示：只在「文件不存在」且满足后文条件时追加。

模型的 HTTP 接口不保存会话。循环每次把当前整份列表重新放进请求。看起来像连续对话，是因为本进程保留了历史。进程退出后这份列表消失。

真实模型看到的系统提示要求六件事：第一轮先写简短计划再调用工具，计划里不写计算结果；`path` 使用相对工作目录的路径；工具失败后更换路径或参数，不把同一次调用原样再试；写入报告的数字必须来自工具返回；工具少时直接调用，不确定某个工具做什么时再用 `tool_search`；完成或确认无法继续时用普通消息作答，不要同时再调用工具。Mock 不读取这份提示。它的步骤由任务原文和已经返回的工具消息决定。

### 一轮多个工具时的顺序

兼容接口规定：带 `tool_calls` 的助手消息后面，必须紧跟这些调用的工具消息，中间不能插入别的角色。循环因此把恢复提示先放在一边。一个工具执行完，只追加它自己的工具消息。这一轮每一个工具都执行完、都记入 Trace 之后，才把暂存的恢复提示追加到列表末尾，并写成 `Recovery Hint`。

于是下一轮送给模型的尾部是：助手消息、工具消息、工具消息、……、然后才可能是恢复提示。不会出现「助手、工具、用户提示、工具」。

## 5. 主循环每一轮

`run_agent` 用一个从 1 数到 `max_steps` 的循环。默认 12。循环内部还记着四件跨轮的状态。

- `planned`：这次运行是否已经写过 `Plan`。
- `last_tool_failed`：上一轮最后一个工具是否失败。决定这一轮能否写 `Plan Update`。
- `last_signature` 与 `streak`：上一次失败的签名，以及这个签名已经连续失败几次。

每一轮按下面的顺序做，不能调换。压缩必须发生在向模型要决定之前，否则模型看见的仍是未压缩的长文本。计划必须写在本轮任何 `Tool Call` 之前。恢复提示必须写在本轮全部 `Tool Result` 之后。

1. 若全部消息的正文字符数超过 24000，压缩更早的工具结果。若压缩条数大于 0，写 `Context Compression`。
2. 调用 `decide(messages, schemas)`。`schemas` 是当前注册表里每一个工具的名称、说明、参数 Schema 和权限。`LLMError` 或其它异常都不执行工具，立刻以 `cannot_continue` 结束。文本分别为「无法继续：模型响应不可用：…」和「无法继续：模型决策失败：…」。这一轮不计入一次成功的工具步骤；结束时报告的轮数是已经完成的轮数。
3. 若本轮有工具调用、还没写过计划、且 `plan` 非空：写 `Plan`，把 `planned` 设为真。
4. 若 `plan_update` 非空且 `last_tool_failed` 为真：写 `Plan Update`。
5. 写 `Agent Decision`，包含轮号、`thought`、工具列表或最终答案、以及存在时的 `usage`。有工具调用时，Trace 里的决定节不重复粘贴最终答案。
6. 若有工具调用，进入下面的「执行一批工具」，然后把 `last_tool_failed` 设成这一批里最后一个工具是否失败，再进入下一轮。
7. 若没有工具调用但 `final_answer` 非空：状态 `final`，轮数就是当前轮号。
8. 若两者都没有：状态 `cannot_continue`，文本为「无法继续：模型没有给出工具调用或最终答案。」
9. 计数用尽仍没有从第 7 或第 8 步返回：状态 `step_limit`。这次不再调用 `decide`。

### 执行一批工具

对列表中的每一项：

1. 编号为空时写成 `call-<轮号>-<序号>`，序号从 1 起。模型若已经给了编号，保留原编号，以便和 HTTP 返回的 `tool_call_id` 对齐。
2. 写 `Tool Call`，内容是名称和按键排序的参数 JSON。
3. 若调用方提供了事件回调，发出 `tool_call`。命令行的默认回调据此打印 `tool: 名称`。
4. 交给注册表 `execute`。注册表返回的永远是结果对象，不抛出给循环。
5. 按 8000 字截断。截断后的文本才进入 Trace 和消息。
6. 写 `Tool Result`：第一行 `ok: true` 或 `ok: false`，下面是文本。
7. 发出 `tool_result` 事件。命令行的默认回调不打印结果正文，只在前面打印过工具名。
8. 追加一条 `role=tool` 的消息。

然后更新连续失败计数，规则见第 8 节。若计数达到 2，先把本轮已经攒下的恢复提示写入消息和 Trace，再以 `cannot_continue` 返回，不再执行这一批里尚未执行的后续工具。

这一批全部执行完且没有因连续失败返回时，再一次性写入恢复提示，然后进入下一轮。

## 6. 上下文的长度

长度看的是每条消息 `content` 的字符数之和，不是 token。

**单条截断。** 工具文本超过 8000 字时，保留前 8000 字，并在末尾加上换行和「已截断」。成功或失败都截断。模型和 Trace 看到的是截断后的同一份，不会一边全文、一边摘要。

**整段压缩。** 求和超过 24000，且工具消息至少有两条时，除最后一条工具消息外，更早的、还没有被压过的工具消息改写成一行：

```text
已压缩：<工具名> 成功|失败：<首行>
```

首行是原文里第一条非空行，去掉两端空白，超过 80 字则只留前 80 字。工具名缺失时写成 `tool`。已经以「已压缩：」开头的消息跳过，避免重复压缩把摘要再切一次。系统提示、用户任务、助手消息和恢复提示不改写。最近一条工具消息保持全文，使模型仍能看见刚刚发生的结果。压缩不调用模型。返回值是本次新压缩的条数；大于 0 时 Trace 写「压缩了 N 条更早的工具结果。」

只有一条工具消息时，即使总长超过 24000 也不做这种压缩，因为没有「更早的一条」可以收起。单条过长仍由 8000 字截断处理。

短任务的工具输出远小于 24000，它们的 Trace 里不会出现 `Context Compression`。这条规则用更低的门槛单独验证，不靠那几句短任务触发。

## 7. 工具注册表

工具不是循环里的条件分支。注册表在运行开始时按本次配置组装，之后 `schemas()` 把整张表交给每一次 `decide`。

默认表的顺序是 `read_file`、`write_file`、`search_text`、`calculator`、`tool_search`。`--sub-agent` 时再在末尾加上 `delegate`。没有这个开关时，模型收到的规格里没有 `delegate`，调用这个名字会得到「未知工具」。

`execute` 的检查顺序固定，前一步失败就不做后一步。

1. 参数不是对象：`参数必须是对象`。
2. 名称不在表中：`未知工具：<名称>`。
3. 该工具的权限不在本次允许集合里：`权限不足：<名称> 需要 <权限>`。执行函数不调用，因此没有写权限时不会创建文件，没有计算权限时不会计算。
4. Schema：每个必填字段都要出现；出现 Schema 未声明的字段则失败；声明为字符串的值必须是字符串，声明为数字的值必须是整数或浮点数，布尔值不算数字。失败文本是「缺少参数：…」「未知参数：…」或「参数类型错误：…」。
5. 调用函数。`ToolError` 变成它自己的消息。其它异常变成 `工具执行异常：…`。两者都是 `ok=false`，不传出循环。
6. 函数正常返回时 `ok=true`，内容就是返回的字符串。

权限和路径是两道闸。权限回答「这次运行准不准做这类事」，路径回答「这个位置在不在工作目录里」。只给 `read` 时，读取和搜索可以成功，写入在第 3 步就被拒绝。路径即便写成 `../secret.txt`，在有 `write` 或 `read` 时仍会在工具内部被沙箱拒绝，错误文本不同。

### 路径沙箱

文件类工具共用 `resolve_inside`。路径不是非空字符串时失败，文本为「路径为空」。相对路径先接到工作目录上，再 `resolve`。绝对路径直接 `resolve`。解析后的真实路径必须是工作目录真实路径的相对下级，否则 `路径超出 workspace：<调用方原始字符串>`。符号链接解析之后若落在外面，同样拒绝。通过检查的路径才允许读或写。工作目录内部的子目录是允许的。

### read_file

权限 `read`。参数只有必填的 `path`。文件存在、是文件、且能按 UTF-8 读取时，返回全文。文件不存在时抛出 `文件不存在：<路径>`，循环把它当成失败结果继续，并可能触发恢复提示。路径越界使用沙箱的那句错误，不触发恢复提示。

### write_file

权限 `write`。必填 `path` 和 `content`，都是字符串。父目录不存在时创建。成功时返回已写入路径的说明。权限在注册表层被拒绝时，函数不会运行，磁盘上不会出现新文件。

### search_text

权限 `read`。必填 `query`，可选 `path`，缺省时从工作目录根开始。`query` 为空字符串则失败，「搜索文本为空」。`path` 先经过沙箱。它指向文件时只搜这个文件，指向目录时递归列出其中的文件。不是文件也不是目录则「搜索路径不存在」。

匹配是子串，区分大小写，不是正则，也不匹配文件名。每个命中一行，`相对路径:行号:该行原文`，行号从 1 开始，路径用 `/`。无法按 UTF-8 解码的文件跳过。没有任何命中时返回空字符串，这次调用仍然成功。因此查询 `sales` 不会仅仅因为存在名为 `data/sales.txt` 的文件就命中；查询正文里的 `product` 可以命中销售数据。

### calculator

权限 `compute`。必填 `expression`。实现用语法树遍历，只接受数字、括号、一元正负号，以及二元的 `+`、`-`、`*`、`/`、`//`、`%`、`**`。不调用 `eval` 或 `exec`，不读取工作目录，表达式里的名字和工作目录无关。

除法结果若能精确表示为整数则写成整数字符串，否则写成浮点文本。`**` 的右操作数绝对值大于 20 时失败，避免指数过大。空表达式、其它运算符、函数调用和名字都失败。成功时的文本就是这个数。任务若要在报告里写合计，应使用这段文本，而不是模型另外心算的数。Mock 的销售步骤就是这样做的：表达式从已经读到的表格拼出来，合计抄计算器的返回。

### tool_search

权限 `read`。必填 `query`。去掉空白后若为空，「查询不能为空」。查找范围是固定的五项：`read_file`、`write_file`、`search_text`、`calculator`、`tool_search`，不包含 `delegate`。在这五项的名称和说明里做字面量包含。命中时每行是 `名称：说明`。没有命中时返回空文本，`ok` 仍为真。它不增删 `schemas()` 的内容。四个基础工具每次请求都在列表里，模型不必先搜索才能读、写、搜索或计算。

### delegate

权限 `read`。只在 `--sub-agent` 时出现在表里。必填 `task`。去掉空白后若为空，失败文本为「子任务不能为空」。否则按下一节启动一层新的 `run_agent`。

## 8. 失败之后循环持有什么

工具失败不是循环的异常。权限、参数、路径、缺失文件、非法算式、子任务没有正常结束，全部是 `ok=false` 加上一段中文说明。这段说明进入消息列表，下一轮 `decide` 能看见它。模型可以改参数、换工具，或在随后一轮给出最终答案。

循环另外维护连续失败。签名是工具名，加上 `sort_keys` 之后的参数 JSON，所以字段顺序不同但内容相同视为同一次调用。

- 本次失败的签名和上一次相同：计数加 1。
- 签名不同：计数改为 1，并记住新签名。
- 本次成功：签名清空，计数归零。

计数达到 2 时立即停止，不再把这次失败交回模型碰运气。最终答案为「无法继续：同一工具和参数连续失败 2 次。」后面附上工具名、参数和错误文本。因此换一条路径可以继续；同一路径连读两次会停。一批工具里若前一个成功、后一个失败，计数按后一个重新从 1 开始。

### 恢复提示

在计数被设为 1 的那一次，若同时满足三点，就暂存一条提示：工具名是 `read_file`；结果文本包含「文件不存在」；结果文本不包含「路径超出」。提示全文固定为：

```text
恢复提示：文件不存在。可以用 search_text 按文件名查找，不要用同一路径再读一次。
```

同一签名只暂存这一次。第二次同一签名会先触发连续失败停止。路径越界不暂存，因为再搜索也出不了工作目录。程序不代模型调用 `search_text`。提示只是多出来的一条用户消息，下一轮由模型自己决定搜不搜、搜什么。

`Plan Update` 与这条提示无关。前者是模型在失败之后自己写的修订，只有决定里带了 `plan_update` 且上一轮最后一个工具失败时才出现在 Trace。后者是循环在特定 `read_file` 失败时插入的上下文。一次恢复运行里可以先有工具失败，再有恢复提示，再在下一轮决定上出现计划修订。

## 9. 下一层循环

父循环执行 `delegate` 时，用同一个 `run_agent` 跑子任务字符串。子循环拿到的工作目录、模型对象、系统提示、8000 与 24000 的长度限制、权限集合，都和父循环相同。两处不同：`max_steps` 为 6；`enable_delegate` 为假，注册表里没有 `delegate`。因此不存在第三层，子循环的 6 轮也不从父循环剩下的轮数里扣除。

子循环的 Trace 目录是父目录下的 `sub/`。父循环没有 Trace 目录时，子循环也不写文件。

子循环返回后，父工具的输出文本是子循环的最终答案，再加一个换行和 `子循环轮数：N`。这里的 N 是子循环报告的 `steps`。若子循环的状态不是 `final`，父工具改为失败，文本以「子任务失败：」开头，后面仍是那段答案和轮数。父循环不根据这句话自动再委托一次。它只是一次普通的工具失败，下一轮父模型自己决定停止或改做别的事。

父 Trace 里能看到的是一次 `delegate` 的 `Tool Call` 和对应的 `Tool Result`。子过程的决定和工具在 `sub/trace.md` 里，不嵌进父文件正文。

## 10. Mock 如何产生决定

Mock 是循环的一个后端，不是另一套循环。`decide` 不看工具 Schema。它用消息里第一条用户原文分类，再只根据已经出现的工具消息决定下一步。分类的优先顺序是：原文含 `data/missing.txt` 则为恢复；否则含 `TODO` 则为汇总；否则含「销售额」则为销售；否则含「非法算式」或 `../` 则为预期失败；都不含则无法归类。

无法归类时没有工具调用。最终答案是「Mock 不能规划该任务。它只处理汇总 TODO、计算销售额、缺失文件恢复，以及越界或非法算式。」未知句子不会假装读过文件或算过数。

四类的工具序列如下。每一步都先看上一条工具消息的 `ok`。失败则给出「无法继续」和那段错误，不再发明下一步。成功才根据那段正文构造下一次调用。

**汇总。** 第一次调用 `search_text`，查询 `TODO`，并带上计划「搜索 TODO，按文件归类后写入 todo-report.md。」搜索结果按 `路径:行号:内容` 拆开，按路径分节，写成报告，第二次调用 `write_file` 写入 `todo-report.md`。写入成功后的最终答案复述搜索到的那些行。

**销售。** 第一次 `read_file`，路径 `data/sales.txt`，计划是读取数据、把数量与单价交给计算器、再写 `report.md`，计划正文不含合计数字。读到的文本要有表头 `product,quantity,price`。每一数据行拼成 `数量*单价`，行与行用 `+` 连接，这就是下一次 `calculator` 的表达式。计算器返回的文本原样进入 `report.md` 的合计。最终答案里的合计也是这段文本。

**恢复。** 第一次读 `data/missing.txt`。这次失败是预期情况：Mock 带上修订「改为搜索 FIXME，再读取销售数据并计算」，然后 `search_text` 查询 `FIXME`，再读 `data/sales.txt`，再计算，再把缺失文件的错误文本、FIXME 命中、表达式和计算器合计写入 `summary.md`。若缺失文件竟然读成功，Mock 停止，并说明预期失败却成功了。

**预期失败。** 原文含「非法算式」时第一次调用 `calculator`，表达式为 `2+`。否则第一次 `read_file`，路径 `../secret.txt`。计划说明只尝试一次，失败就停止。工具失败后不再发起第二次调用，最终答案是「无法继续：」加上工具错误，并带修订「不再用同一路径或同一算式重试」。若这次工具竟然成功，同样停止。

每一类都有步数上限。工具消息条数超过上面的序列时，最终答案说明超出 Mock 计划，不再继续调用。

## 11. OpenAI 兼容后端

适配器在构造时就要求密钥、基地址、模型名三者都非空，否则 `LLMError`，命令行因此在进入循环前退出。基地址去掉末尾斜杠后，请求发到 `{基地址}/chat/completions`。DeepSeek 使用 `https://api.deepseek.com`，程序不追加 `/v1`。官方 OpenAI 的基地址本身带有 `/v1`，程序也不删除它。

请求是 JSON。`temperature` 为 0。`messages` 由当前列表逐条转换：普通消息保留角色和正文；带工具调用的助手消息增加 `tool_calls`，每项为 `id`、`type: function`、`function.name`、`function.arguments`（参数对象再编成 JSON 字符串）；工具消息的角色是 `tool`，并带 `tool_call_id` 和 `name`。`tools` 来自注册表，每项包成 `type: function`，其中有名称、说明和参数 Schema。权限字段留在循环内部的规格里，不放进这份 HTTP 工具对象。

超时 30 秒。一次决定最多请求 3 次（首次加 2 次重试）。HTTP 状态码小于 500，包括 4xx，立刻失败，不重试，错误文本含状态码和响应体。5xx、连接失败和超时才会再试；最后一次仍失败则把原因包进 `LLMError`。本机工具返回的「文件不存在」或「权限不足」不会触发这层重试，它们根本不是这次 HTTP。

响应必须是 JSON 对象，且 `choices[0].message` 存在。有 `tool_calls` 时逐项解析名称和参数；参数字符串必须是 JSON 对象。该消息的 `content` 去掉空白后若非空，同时成为 `thought` 和 `plan`；为空则 `thought` 为「调用工具」，`plan` 为空。没有工具调用时，`content` 必须是非空字符串，否则视为响应不可用；这段字符串既是 `thought` 也是 `final_answer`。顶层 `usage` 若是对象则保留。

线上这一次 HTTP 取回的是完整 JSON，不是分片。`StreamAssembler` 只服务已经录好的分片测试：它把增量正文和增量参数拼起来，参数还不是完整 JSON 时不产出工具调用。线上的 `decide` 不经过它。

## 12. Trace 与终端

记录器在内存里同时维护 Markdown 行和事件列表。循环结束时若给了目录，一次写出 `trace.md` 和 `trace.jsonl`。Markdown 以 `# Agent Trace` 开头，每个事件一个 `##` 标题。JSONL 一行一个对象，用 `type` 区分。

| Markdown 标题 | `type` | 何时写入 |
| --- | --- | --- |
| `User` | `user` | 进入循环时，正文是任务原文 |
| `Plan` | `plan` | 第一次工具调用之前，决定带有计划 |
| `Plan Update` | `plan_update` | 上一轮最后一个工具失败，且决定带有修订 |
| `Agent Decision` | `agent_decision` | 每一轮。含 `step`、`thought`、工具或 `final_answer`、可选 `usage` |
| `Tool Call` | `tool_call` | 注册表执行之前 |
| `Tool Result` | `tool_result` | 执行之后，含 `ok` 和截断后的文本 |
| `Recovery Hint` | `recovery_hint` | 本轮工具结果都已写下，且暂存了文件不存在的提示 |
| `Context Compression` | `context_compression` | 本轮 `decide` 之前实际压缩了至少一条 |
| `Final Answer` | `final_answer` | 三种结束都会写。含 `status` 和最终文本 |

没有发生的节不会占位。短任务没有压缩节。真实模型没有修订节。没有读到缺失文件就没有恢复提示节。越界失败不会因为「失败了」就出现恢复提示。

事件回调和 Trace 是两条输出。回调的种类是 `tool_call`、`tool_result`、`final`。命令行默认只把 `tool_call` 打成 `tool: 名称`，把 `final` 打成答案。`tool_result` 留给 Trace。`--no-stream` 不注册回调，答案在 `run_agent` 返回后打印一次。

下一层有自己的记录器。它的两份文件在父 Trace 目录的 `sub/`，结构与父文件相同，其中不会再出现 `delegate` 的工具调用。

## 13. 这套设计用哪些句子验收

循环内部没有 TODO、销售额或 `secret.txt` 的分支。仓库用四句固定原文驱动 Mock，并给真实模型同一批句子，用来观察读、写、搜索、计算、缺失文件和越界路径是否按上面的规则发生。原文在 `mini_agent/tasks.py`。工作目录由 `scripts/generate_workspace.py` 准备。怎么跑、结果看哪一份 Trace，写在 `docs/TASKS.md`。

## 14. 设计要求里的七个问题

### Agent Loop 如何设计

主循环在 `run_agent`。一次运行保存一份消息列表，默认最多向模型要 12 次决定。每一轮先按长度压缩上下文，再调用 `decide`。决定里若有工具调用，就按顺序执行，把每条结果追加回列表，然后进入下一轮。决定里只有最终答案时结束。两者同时出现时只执行工具，最终答案必须出现在没有工具调用的下一轮。

第一次工具调用之前，若决定带有计划，先写入 Trace。上一轮最后一个工具失败且决定带有修订时，写入计划修订。文件不存在的恢复提示先暂存，等这一轮全部工具结果都写完再追加，避免插在同一次助手回复的两条工具消息中间。

模型不可用、没有给出行动、同一签名连续失败两次，或轮数用尽，都结束并给出说明。下一层循环是同一次函数的再入，最多 6 轮，且不能再委托。

### Tool 如何定义

每个工具是注册表里的一项：名称、说明、JSON Schema、一种权限、一个执行函数。默认注册 `read_file`、`write_file`、`search_text`、`calculator`、`tool_search`。`--sub-agent` 才加上 `delegate`。每次 `decide` 都收到当前这张表的全部规格。

调用时依次检查参数是不是对象、名称是否存在、权限是否允许、Schema 是否满足，然后才执行函数。任一步失败都返回 `ok=false` 和说明，函数不会被调用。`read`、`write`、`compute` 三种权限默认都允许，`--allow` 可以收紧。文件路径必须解析后仍在工作目录内。`calculator` 用语法树计算，不用 `eval`。`tool_search` 只做查找，不从规格列表里拿掉其它工具。

### 如何判断任务结束

循环在三种情况下结束，每种都有最终文本。

- 模型给出最终答案，且该轮没有工具调用。状态 `final`。
- 决策轮数达到上限，默认 12。状态 `step_limit`，此后不再请求模型。
- 无法继续。状态 `cannot_continue`。原因是模型没有给出工具调用或最终答案，模型响应无法使用，或同一工具、同一参数连续失败两次。

子循环未以 `final` 结束时，父循环只是收到一次失败的工具结果，父任务是否结束仍由父循环的下一次决定。

### 如何避免无限调用

三道限制同时生效。决策轮数有上限，用尽后不再调用模型。同一失败签名最多连续出现两次，签名是工具名加上按键排序的参数 JSON，第二次立即停止。一次成功或换一组参数会把计数清零。Mock 对每一类已知任务还有固定步数，超出后直接结束，不再发明工具调用。子循环另有 6 轮上限，并且工具表里没有 `delegate`，委托不会叠下去。

### Tool 执行失败如何处理

失败是一条普通的工具结果，循环不因此崩溃。权限不足、参数不合法、路径越界、文件不存在、算式非法、子任务未完成，都是 `ok=false` 和一段说明。这段说明进入下一轮消息，由模型决定改参数、换工具或结束。

`read_file` 报告文件不存在、且不是路径越界、并且是该签名的第一次失败时，循环在本轮工具结果全部写完后追加一条恢复提示，建议用 `search_text` 查找，且不要用同一路径再读。程序不代替模型发出搜索。同一签名再失败一次则停止，最终答案写明工具名、参数和错误。

HTTP 的超时、连接错误和 5xx 只在模型适配器内重试，最多再试 2 次。4xx 不重试。工具在本机返回的失败不走这层重试。

### Agent、LLM、Tool、Context 如何划分职责

Agent 是循环。它掌握轮数、停止、连续失败、恢复提示的位置、上下文压缩和 Trace。它不理解业务文件的内容。

LLM 只看消息和工具规格，产出一次 `Decision`。它不执行工具，不碰工作目录。Mock 和 OpenAI 兼容接口实现同一个 `decide`。

Tool 校验参数并做一件事，返回成功文本或失败文本。它不决定下一步。`delegate` 的函数只是再打开一个不能继续委托的循环。

Context 是消息列表：系统提示、用户任务、助手决定、工具结果、必要时的恢复提示。单条工具输出超过 8000 字会截断。全部消息超过 24000 字时，更早的工具结果收成一行，最近一条保持全文。压缩不调用模型。

### 当前实现最大的限制是什么

一次进程只处理一句任务，退出后没有会话可以继续。

Mock 只按四类原文选择步骤：汇总 TODO、计算销售额、缺失文件后恢复、越界或非法算式。其它说法得到「Mock 不能规划该任务」，不产生工具调用。查找工具和子代理的真实过程来自 OpenAI 兼容接口。

真实模型依赖调用方提供密钥、地址和模型名。适配器不产生计划修订。线上请求一次返回完整 JSON，终端上的逐工具打印不改变这次 HTTP。单条工具输出超过 8000 字时，后半不会进入下一轮。`search_text` 匹配文件内容，不匹配文件名。子代理只有一层。
