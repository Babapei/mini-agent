# Kubernetes 故障诊断 SRE Agent

**适用方向：容器与算力平台稳定性开发工程师**

## 题目：主题 / 场景设定

业务运行在 Kubernetes 集群中。

某天用户发现：

> “我的应用 job-123 为什么失败了？”

系统中可能存在以下信息：

* Pod Status
* Kubernetes Event
* Node Status
* CPU / Memory Metrics
* Application Log

用户通常需要人工执行多个命令：

```bash
kubectl get pod
kubectl describe pod
kubectl get events
kubectl get node
kubectl logs
```

才能定位问题。

请设计并实现一个 **Kubernetes 故障诊断 SRE Agent**。

用户输入：

> “帮我分析 job-123 为什么失败。”

Agent 应自动决定需要查询哪些信息，并最终给出诊断结论。

推荐产品形态：

**对话式 Agent + 故障诊断结果页面**

允许使用 Mock Kubernetes 数据，不要求搭建真实生产集群。

## 必须支持

至少提供以下工具：

* GetPod
* GetPodEvents
* GetNode
* GetMetrics
* GetLogs

Agent 根据问题选择调用相应工具。

至少支持以下 5 类故障：

* OOMKilled
* Node NotReady
* Scheduling Failed
* DiskPressure
* 网络 / 服务连接超时

诊断结果至少包含：

**故障现象**

发生了什么。

**关键证据**

哪些 Event、Metric 或 Log 支持这个判断。

**可能原因**

系统判断出的故障原因。

**处理建议**

用户接下来可以进行什么操作。

系统需要明确区分：

* 已确认事实
* 根据证据推测的可能原因

同时需要：

* 保存一次完整诊断过程
* 展示 Agent 调用了哪些工具
* 支持查看每次工具调用结果
* Agent 无法确定原因时，应明确说明证据不足，而不是强行给出结论

## 加分能力

* 故障知识库 / RAG
* 自动匹配历史相似 Case
* 支持 Prometheus / Loki / OpenTelemetry
* 支持 GPU Xid / NCCL 等 AI Infra 故障
* 自动生成故障复盘报告
* 给出自动修复方案
* 修复动作执行前需要人工确认
* 修复完成后自动检查问题是否恢复
