# Agentic RL Sandbox Pool 调度系统

**适用方向：大模型训练 Sandbox 开发工程师**

## 题目：主题 / 场景设定

Agentic RL 训练过程中，一个训练任务可能需要执行大量 Rollout。

假设每个 Rollout 都需要一个 Sandbox：

```text
Rollout A：运行 3 秒
Rollout B：运行 10 秒
Rollout C：运行 40 秒
Rollout D：运行 5 秒
……
```

假设：

* 创建一个 Sandbox 需要 500ms
* Reset 一个已有 Sandbox 需要 20ms
* 每台机器可以同时运行的 Sandbox 数量有限

如果每次 Rollout 都新建 Sandbox，会产生大量创建开销。

如果一直保留大量 Sandbox，则可能浪费机器资源。

请设计一个 **Sandbox Pool 调度系统**，在启动速度和资源占用之间进行权衡。

推荐产品形态：

**Scheduler Simulator + Dashboard / CLI**

本题允许完全使用 Simulator 实现，不要求使用真实 Docker / Kubernetes。

## 必须支持

* Sandbox Pool
* Sandbox Acquire / Release
* Sandbox Reset
* 空闲 Sandbox 回收
* Sandbox 创建失败后的异常处理
* 支持至少 100 个 Rollout 的模拟执行
* 支持不同执行时间的 Rollout
* 至少实现两种执行方式：

方案 A：

**每个 Rollout 都创建新 Sandbox**

方案 B：

**使用固定大小 Sandbox Pool**

需要对比：

* Sandbox 创建次数
* Sandbox 复用率
* Rollout 平均等待时间
* P95 等待 / 启动时间
* 最大同时运行 Sandbox 数量

并回答：

> 什么情况下 Pool 太小？

> 什么情况下 Pool 太大会造成资源浪费？

## 加分能力

* 根据任务量自动扩大 / 缩小 Pool
* 长短任务分池
* 任务优先级
* 多台 Node 调度
* Sandbox 故障自动补充
* 根据历史负载预测 Pool Size
* 使用真实 Docker / Kubernetes 实现 Sandbox Pool
* 对接一个简单 Agent / RL Rollout 示例
