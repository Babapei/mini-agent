## 题目：实现一个能够自主调用工具完成任务的 Mini Agent

请实现一个简化版 AI Agent。

Agent 接收到用户自然语言任务之后，需要根据任务自主判断应该调用哪些工具，并根据工具返回结果决定下一步操作，直到完成任务或者判断任务无法继续完成。

至少提供以下 Tool：

```text
read_file
write_file
search_text
calculator
```

例如用户输入：

```text
找出 workspace 目录中所有 TODO，
按照文件进行分类并生成 todo-report.md。
```

Agent 可能执行：

```text
理解用户目标
    ↓
search_text
    ↓
获得搜索结果
    ↓
read_file
    ↓
分析内容
    ↓
write_file
    ↓
返回最终结果
```

另一个测试任务：

```text
读取 sales.txt 中的数据，
计算所有产品销售额之和，
并把计算结果写入 report.md。
```

### 基础功能要求

至少需要实现：

1. Agent 主循环。
2. Tool 定义和注册机制。
3. Tool 参数解析。
4. Tool 调用。
5. Tool Result 返回 Agent。
6. Agent 根据 Tool Result 判断下一步行为。
7. 支持一次任务中连续调用多个 Tool。
8. 最终答案输出。
9. Agent 执行轮数控制，避免无限循环。
10. Tool 调用失败时能够进行合理处理。

模型可以：

- 使用任意可以访问的模型 API；
- 使用本地模型；
- 在模型条件确实受限时使用 Mock LLM 完成部分验证。

不要求复杂 UI，CLI 即可。

### 测试材料生成

候选人自行建立一个 `workspace`。

建议结构：

```text
workspace/
├── README.md
├── src/
│   ├── user.ts
│   └── order.ts
├── docs/
│   └── design.md
└── data/
    └── sales.txt
```

不同文件中建议包含：

- TODO；
- FIXME；
- 普通代码；
- 数字数据；
- 文本说明；
- 部分不存在的目标；
- 可能导致 Tool 失败的输入。

候选人需要至少自行设计 **3 个不同类型的 Agent 任务**。

例如：

1. 搜索并汇总；
2. 读取、计算并生成报告；
3. 需要多次 Tool 调用才能完成的任务。

### 可选增强项

包括但不限于：

- Tool Schema；
- Tool 参数校验；
- Tool Permission；
- Tool 调用失败自动恢复；
- Retry；
- Timeout；
- Agent Trace；
- Token Usage；
- Context Compression；
- Plan；
- Sub Agent；
- Streaming；
- 防止读取 workspace 之外的文件；
- Tool Search；
- 对执行计划动态调整。

## 候选人提交要求-交付物

至少提交：

1. **完整源代码**。
2. **README**。
3. **Agent 启动和使用说明**。
4. **测试 workspace 或生成脚本**。
5. **至少 3 个不同测试任务及实际执行结果**。
6. **至少一份完整 Agent Trace**，能够体现：

```text
User
↓
Agent Decision
↓
Tool Call
↓
Tool Result
↓
Agent Decision
↓
Tool Call
↓
...
↓
Final Answer
```

7. **AI 工具完整对话过程**：
   - 提交考试期间与 AI Coding 工具的主要对话；
   - 包括需求分析、Agent 架构设计、实现、调试和测试等过程；
   - 应能够看出候选人如何指导 AI，以及 AI 输出出现问题后如何处理。
8. **AI_USAGE.md**，总结：
   - AI 参与了哪些环节；
   - 哪些关键设计由候选人决定；
   - AI 出现过哪些错误判断；
   - 候选人如何发现并修正。
9. **设计说明**，至少回答：
   - Agent Loop 如何设计；
   - Tool 如何定义；
   - 如何判断任务结束；
   - 如何避免无限调用；
   - Tool 执行失败如何处理；
   - Agent、LLM、Tool、Context 如何划分职责；
   - 当前实现最大的限制是什么。
